**No migration path over a foreign `changelog.d/`** (#167): `install.sh --changelog-fragments` over a directory another tool owns warned that `--check` would reject the existing filenames, then left the operator to sort it out by hand — and only once, since adoption scaffolded our README into the directory, which suppressed the warning on every later run while the foreign fragments still sat there. Verified against scriv's actual conventions, an automatic rename has no target: a scriv fragment keeps its category inside the body, one file can hold several, and the files are not ours to rewrite. The warning now fires whenever `changelog.d/` holds a file `collect-changelog.sh` cannot fold (dotfile placeholders like `.gitkeep` no longer trigger it), states what the tooling actually sees — `--check` rejects foreign `.md` names and never inspects the rest, so scriv's `.rst` default would sit unfolded silently — and names the migration path: fold pending fragments with the tool that wrote them (`scriv collect`), documented in the scaffolded `changelog.d/README.md` and the README.
