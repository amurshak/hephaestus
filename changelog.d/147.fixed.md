**Cursor `readonly:` now reflects what Cursor actually does** (#147): the flag was emitted only for agents with no shell, because whether `permissionMode READONLY` also withheld the terminal was unknown. Probed against Cursor 3.13.21: it runs the shell under a read-only filesystem sandbox — a shell write fails with `operation not permitted` — drops only `SwitchMode`, and leaves both `Shell` and `Write` in the tool list, where the write tool bypasses the sandbox entirely. `reviewer` and `explorer` therefore carry `readonly: true` now, gaining a sandboxed shell they previously ran without. `tester` is exempt through a new `shell: write` frontmatter key, since test runs produce artifacts and a sandboxed shell would fail the test command outright. The generated prose claimed `readonly: true` withholds write tools; it does not, and the write tool is not sandboxed, so the note now says what the flag actually guarantees rather than overselling it. Also drops a stale `.hephaestus/` submodule reference from the generated Cursor rule, left behind by the submodule removal in #140.
