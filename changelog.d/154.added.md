**`verify-hermes-load.sh --live`** (#154): every check the verifier ran was a layout assertion, which proves a skill *resolves* but never that Hermes injects its **body** — `-s` could preload nothing but the description and the script would still report a healthy install. That is not hypothetical: #154 lost two measurement runs to a session whose workflow the model never received, and the gap was invisible because the free checks all passed. Nothing offline closes it (`hermes skills inspect` reads registries rather than local dirs, and `hermes prompt-size` reports the skills index only), so `--live` spends one inference call to ask the model whether a sentence carried solely by the body is present. It is opt-in precisely because the default must stay free for quality gates. Measured discriminating rather than vacuous: `-s hephaestus/start-issue` answers OK while `-s hephaestus/ship` and a bare session both answer MISSING, and a chat that cannot answer is reported inconclusive and fails instead of passing — the false-healthy result the flag exists to prevent. Covered in `tests/test_hermes_adapters.sh`, including that the default path never invokes `hermes chat`.
