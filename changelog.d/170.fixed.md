**CLAUDE.md understated the Cursor spawn form** (#170): the Cursor bullet under "Key Design Constraints" still read "the `/worktrees` spawn CLI localizes to `cursor-agent`" after #169 changed it to `cursor-agent -p`. Wrong by omission, and the omission is the load-bearing half — measured against a live cursor-agent 2026.07.23-e383d2b, Cursor's slash dispatcher is bound to the TUI input widget, so a bare positional `/start-issue <N>` reaches the model as literal text and, for the default user-level install, the spawned session never starts the issue at all. `scripts/verify-cursor-load.sh` guards the flag's existence in the CLI but not a hand-edit to the generator, so the doc line is what stands between a future editor and silently un-dispatching every spawned Cursor session. The bullet now states the flag, why it is required, and that Cursor spawns are consequently headless — `-p` prints and exits — so the Cursor row reading differently from the Claude and Codex rows registers as deliberate rather than as an oversight.
