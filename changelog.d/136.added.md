**Changelog fragments for target projects** (#136): `install.sh --project|--vendor
--changelog-fragments` scaffolds `changelog.d/`, a `CHANGELOG.md` if absent, a copy of
`scripts/collect-changelog.sh`, and `CHANGELOG.md merge=union` in `.gitattributes`, so a
repo's changelog stops being the file every PR conflicts on. Opt-in, because unlike every
other scaffold it changes *where* `/ship` writes; sticky afterwards — later runs and
`update.sh` recognize the adoption and keep it without the flag. Because project mode
writes no manifest, recognition takes both `changelog.d/` and a collect script carrying
our header, so a repo with its own `scripts/collect-changelog.sh` is never read as an
adopter and never has that file overwritten, `--force` included. Our own copy is code
rather than a customization point, so it is refreshed under `--force` once it drifts.
