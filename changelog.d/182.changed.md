**`loop.sh` runs every harness, not two** (#182): headless mode was the last Claude/OpenCode-shaped hole in an otherwise harness-neutral distribution — five harnesses got the full workflow interactively and only two got anything across time. `HEPH_HARNESS` now takes `claude`, `codex`, `cursor`, `hermes`, or `opencode`, dispatched through one table of binary + argv that replaces the two-branch `case` and the two-branch `run_session`. The PATH guard reads the same table, so it names the binary that is actually missing (`cursor-agent`, not `cursor`) and offers every harness except the one just rejected, instead of the old hardcoded "or set `HEPH_HARNESS=opencode`" in both directions. Each form is the harness's own *non-interactive* mode rather than the TUI-seeding form `/worktrees` spawns — for Codex that means `codex exec`, not the bare positional prompt, because an interactive session never exits and the loop would never reach its sleep. The three harnesses with no expressed unattended story now have one, established against live CLIs: `codex exec --dangerously-bypass-approvals-and-sandbox` (exec mode has no `--ask-for-approval` at all — with no TTY there is nobody to ask — so the sandbox is the only gate, and it must be open or `git push`/`gh` fail on blocked network), `cursor-agent -p --force --trust` (`-p` is both the non-interactive mode and what dispatches the slash command; `--trust` answers a workspace prompt that would otherwise block), and `hermes chat -s hephaestus/autopilot -q … --yolo --accept-hooks` (`-q` bypasses the slash dispatcher so `-s` preloads the skill; hooks are a second gate `--yolo` does not cover). The session's stdin is now `/dev/null`: `codex exec` reads stdin whenever one is attached, which would hang an unattended loop forever. `tests/test_loop.sh` is table-driven over all five for both dispatch and the PATH-guard message.

Two findings from the pre-ship critique are folded in. The dispatch test asserts the **complete, ordered** argv rather than token presence: order is the invariant that matters, and a token-presence check let three real mutations ship green — `-q --accept-hooks` (Hermes swallows the hooks flag as its query text), a Codex subcommand demoted to a trailing positional, and a deleted stdin redirect. A FIFO-backed regression test now holds the redirect specifically, since inheriting the runner's stdin would pass vacuously wherever stdin is already closed. And the Hermes query carries its own guard: it is the one harness that fails *silently*, because a `-s` resolving to nothing starts the session with no skill loaded instead of aborting — which unattended, with `--yolo --accept-hooks`, would leave a fully-approved agent looping in a git repo on nothing but a one-line instruction.
