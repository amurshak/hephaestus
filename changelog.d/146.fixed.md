**Test fixtures no longer copy gitignored build artifacts** (#146): `setup_fixture` rsynced the working tree with only `.git` excluded, so every gitignored artifact was copied once per fixture — on a checkout where OpenCode has run, `.opencode/node_modules` is ~61MB, or ~800MB across `test_install.sh`'s 13 fixtures. The suite ran 25m53s at 9% CPU locally and sometimes died with `rsync: unexpected end of file`; CI never saw it because CI clones fresh. `test_install.sh` now runs in ~34s and the full suite in ~1m42s. The exclude list is generated by `git ls-files --others --ignored --exclude-standard --directory` rather than handed to rsync as `--filter=':- .gitignore'`: rsync cannot read git's negation syntax and would parse `.hermes/.gitignore` (`*` plus `!skills/**`) as a bare `*`, silently dropping that whole tree from every fixture. The list is built with `env -u GIT_CONFIG_GLOBAL` so the fixture's own git config cannot hide a `core.excludesFile` rule, with `core.quotePath=false` so non-ASCII names still match, and with glob metacharacters escaped so an ignored `a[bc].log` cannot exclude tracked `ab.log`. New `tests/test_fixture_hygiene.sh` pins all three properties: ignored artifacts stay out, untracked working-tree files come in, and uncommitted edits to tracked files under an ignore-all `.gitignore` still reach the fixture.
