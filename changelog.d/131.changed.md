**User-level install is the default** (#131): `install.sh` with no arguments symlinks the shared commands and agents into the harness config dirs — `~/.claude/{commands,agents}`, `~/.config/opencode/{commands,agents}`, `~/.codex/{skills,agents}`, `~/.hermes/{skills/hephaestus,agents}`, honoring `$CLAUDE_CONFIG_DIR`, `$XDG_CONFIG_HOME`, `$CODEX_HOME`, and `$HERMES_HOME` — so one install covers every project and every harness. `install.sh --project <path>` scaffolds only what a repo genuinely owns (`orient` × 4 harnesses, `AGENTS.md`, `opencode.json`, `.hermes/.gitignore`, `CLAUDE.md` validation); `install.sh --vendor <path>` adds committed copies for teams that want the workflow pinned alongside the code. Ownership is now recorded rather than inferred: every mode writes a manifest of the paths it created (`$XDG_STATE_HOME/hephaestus/manifest`, or `<project>/.heph-manifest` when vendored), and install, `--clean`, `update.sh`, and `uninstall.sh` all read it — so a file hephaestus did not write is never modified or removed, and an adapter dropped upstream is detected exactly instead of guessed from symlink targets. `update.sh` pulls the clone and re-installs (`--vendor <path>` for a vendored repo); `uninstall.sh` removes exactly what the manifest lists. `loop.sh` runs from the clone (`~/.hephaestus/loop.sh`) with the project as cwd. For Hermes this removes the `skills.external_dirs` wiring step entirely: the package lands in `~/.hermes/skills/hephaestus/`, which Hermes already reads, so it works in every project without a config edit.
