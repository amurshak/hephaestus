**`/worktrees` adapters spawned the wrong harness** (#129): the Step 6 spawn block's `claude --permission-mode default "/start-issue <N>"` passed through the OpenCode and Codex generators verbatim, so a non-Claude `/worktrees` run launched `claude` with a Claude-only flag. Both localizers now rewrite the spawn CLI and its rationale — OpenCode to `opencode --prompt "/start-issue <N>"`, Codex to `codex "/start-issue <N>"` — for the `osascript` launch and the manual-launch fallback alike. Neither harness inherits plan mode, so `--permission-mode` is dropped rather than mapped. The workflow summary line ("spawn a seeded Claude Code session") is localized too, and both generators now build the routing `description:` frontmatter from the localized first body line rather than the raw one — previously a Claude product name stayed out of the Codex skill router only because the 180-char truncation happened to cut before it. A repo-wide test guard fails on any `Claude Code`, `claude -`, or `--permission-mode` reference surviving in a generated OpenCode or Codex adapter.
