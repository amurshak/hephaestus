**Hermes integration — skill package** (#108): `scripts/sync-hermes-adapters.sh` emits Hermes skills (`.hermes/skills/hephaestus/<name>/SKILL.md`) from `.ai/workflows/` and `delegate_task` briefs (`.hermes/agents/<name>.md`) from `.claude/agents/`, with sync + `--check`, stale-adapter detection, non-generated-dir protection, and an unparseable-source guard. Hermes is a skills harness, not a command-file harness, so the unit of distribution is a skill package under a `hephaestus` category rather than a commands directory. Skill frontmatter follows Hermes convention (`name`, ≤60-char `description`, `platforms`, `metadata.hermes.{category,tags,requires_toolsets,related_skills}` — `chains` maps to `related_skills`); bodies rewrite Claude dialect into Hermes mechanics (`delegate_task` with per-role `toolsets`, the todo tool, serialize edits) and warn that a delegate inherits none of the parent conversation. Delegate briefs carry real per-role toolset narrowing (`["terminal", "file"]` for coder, `["file", "web"]` for researcher), `role: "leaf"`, and read-only / no-worktree-isolation caveats. `install.sh` / `update.sh` / `uninstall.sh` symlink skills and briefs (orient skill scaffolded project-specific); since Hermes has no project-local skill discovery, install prints the one-time `skills.external_dirs` wiring and `scripts/verify-hermes-load.sh` verifies it against a live install. Model tiers render advisory — Hermes applies one global `delegation.model`. Verified against Hermes Agent v0.15.1: all 13 skills load under the `hephaestus` category. Covered by `tests/test_hermes_adapters.sh` plus install lifecycle checks.
