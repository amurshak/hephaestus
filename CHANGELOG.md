### Added
- **Cursor adapter generator** (#107): `scripts/sync-cursor-adapters.sh` emits Cursor slash commands (`.cursor/commands/<name>.md`) from `.ai/workflows/`, Cursor subagents (`.cursor/agents/<name>.md`) from `.claude/agents/`, and an always-apply project rule (`.cursor/rules/hephaestus.mdc`) derived from both, with sync + `--check`, identity-scoped stale detection, and an unparseable-source guard. Cursor mechanics were read off the shipped bundle: commands are injected verbatim (frontmatter is stripped only for imported `.claude/commands`), so adapters carry no YAML and lead with the workflow's opening line — Cursor's hover preview — while `$ARGUMENTS`/`$1`… *are* substituted and survive. Frontmatter values are not unquoted, so they are emitted bare; `readonly: true` is honoured (it maps to a READONLY permission mode) and is emitted for `researcher`, while `reviewer`, `tester`, and `explorer` need a working shell and keep the default mode, carrying the restriction as instruction exactly as they do under Claude Code — `tools:` is rendered to the model as prose in Cursor and is never an access control. The `/worktrees` spawn CLI localizes to `cursor-agent`, guarded repo-wide against Claude-product leaks the way #129 guards the other harnesses. `install.sh` picks Cursor up as three rows in `adapter_rows()`, so user, `--project`, and `--vendor` modes all work and the manifest makes ownership exact — `.cursor/rules/` is shared with the project's own rules and hephaestus only ever writes `hephaestus.mdc`. `.ai/models.conf` gains a `cursor` section with no shipped defaults, since Cursor's model namespace churns per release. Covered by `tests/test_cursor_adapters.sh` plus Cursor coverage across the install, uninstall, and update suites.

### Changed
- **User-level install is the default** (#131): `install.sh` with no arguments symlinks the shared commands and agents into the harness config dirs — `~/.claude/{commands,agents}`, `~/.config/opencode/{commands,agents}`, `~/.codex/{skills,agents}`, `~/.hermes/{skills/hephaestus,agents}`, honoring `$CLAUDE_CONFIG_DIR`, `$XDG_CONFIG_HOME`, `$CODEX_HOME`, and `$HERMES_HOME` — so one install covers every project and every harness. `install.sh --project <path>` scaffolds only what a repo genuinely owns (`orient` × 4 harnesses, `AGENTS.md`, `opencode.json`, `.hermes/.gitignore`, `CLAUDE.md` validation); `install.sh --vendor <path>` adds committed copies for teams that want the workflow pinned alongside the code. Ownership is now recorded rather than inferred: every mode writes a manifest of the paths it created (`$XDG_STATE_HOME/hephaestus/manifest`, or `<project>/.heph-manifest` when vendored), and install, `--clean`, `update.sh`, and `uninstall.sh` all read it — so a file hephaestus did not write is never modified or removed, and an adapter dropped upstream is detected exactly instead of guessed from symlink targets. `update.sh` pulls the clone and re-installs (`--vendor <path>` for a vendored repo); `uninstall.sh` removes exactly what the manifest lists. `loop.sh` runs from the clone (`~/.hephaestus/loop.sh`) with the project as cwd. For Hermes this removes the `skills.external_dirs` wiring step entirely: the package lands in `~/.hermes/skills/hephaestus/`, which Hermes already reads, so it works in every project without a config edit.
- Separated the product surface (what an installed project consumes) from the contributor surface (what maintaining hephaestus requires). `.ai/conventions.md` is the single-source behavior spec; the workflows restate each retry limit at the point of use, so `/orient` no longer retypes a `## Workflow Rules` block into every target project and `templates/CLAUDE.md.snippet` no longer carries a hand-synced copy. `/finish`'s docs rule lost its repo-specific examples in favour of a `## Docs Requirements` override in CLAUDE.md, under which generated adapters require no docs — which un-pins doc-touching work from one issue per `/worktrees` wave. `tests/check_conventions.sh` fails on drift between the spec and the workflows.
- Named the config-surface rule in CLAUDE.md's Configuration Surfaces section: script-consumed values go in a config file with the `models.conf` layering, agent-read values stay CLAUDE.md prose. The audit against it found every current setting already on the right side — retry limits and critique thresholds stay prose, recorded as settled so the question stops being reopened.
- **An unmodified `collect-changelog.sh` now refreshes without `--force`** (#163): project mode writes no manifest, so the distributed copy was recognized only by its `# hephaestus:collect-changelog` provenance token — which proves we wrote the file but not whether it has changed since. `update.sh` re-runs `install.sh` without `--force`, so an adopted project that fell behind got `[skip] collect-changelog.sh (differs from this clone — refresh with --force)` on every update and never a refresh, and `--force` is repo-wide: reaching for it to pick up a one-script fix also replaces same-named adapters the operator may have hand-edited. Every adopted project hit this the first time the script changed upstream. The copy is now stamped as `# hephaestus:collect-changelog v<version> sha=<checksum>` when it lands, recording the clone version and a checksum of the pristine source, which separates the two states the bare token conflated: a copy that still hashes to its recorded checksum is provably untouched and is refreshed in place with no flag, while one that does not is the operator's and is preserved and reported until `--force` is passed. This also resolves the `status=stale` conflation noted in the same issue. Copies written before stamping are handled conservatively — edited and stale are indistinguishable there, so a drifted one keeps the old `--force` behavior; one identical to the clone is simply stamped, and self-heals from the next upstream change onward. `update.sh`'s adoption probe was anchored at `$` and would no longer have matched a stamped line, so it now accepts both forms.
- **`loop.sh` runs every harness, not two** (#182): headless mode was the last Claude/OpenCode-shaped hole in an otherwise harness-neutral distribution — five harnesses got the full workflow interactively and only two got anything across time. `HEPH_HARNESS` now takes `claude`, `codex`, `cursor`, `hermes`, or `opencode`, dispatched through one table of binary + argv that replaces the two-branch `case` and the two-branch `run_session`. The PATH guard reads the same table, so it names the binary that is actually missing (`cursor-agent`, not `cursor`) and offers every harness except the one just rejected, instead of the old hardcoded "or set `HEPH_HARNESS=opencode`" in both directions. Each form is the harness's own *non-interactive* mode rather than the TUI-seeding form `/worktrees` spawns — for Codex that means `codex exec`, not the bare positional prompt, because an interactive session never exits and the loop would never reach its sleep. The three harnesses with no expressed unattended story now have one, established against live CLIs: `codex exec --dangerously-bypass-approvals-and-sandbox` (exec mode has no `--ask-for-approval` at all — with no TTY there is nobody to ask — so the sandbox is the only gate, and it must be open or `git push`/`gh` fail on blocked network), `cursor-agent -p --force --trust` (`-p` is both the non-interactive mode and what dispatches the slash command; `--trust` answers a workspace prompt that would otherwise block), and `hermes chat -s hephaestus/autopilot -q … --yolo --accept-hooks` (`-q` bypasses the slash dispatcher so `-s` preloads the skill; hooks are a second gate `--yolo` does not cover). The session's stdin is now `/dev/null`: `codex exec` reads stdin whenever one is attached, which would hang an unattended loop forever. `tests/test_loop.sh` is table-driven over all five for both dispatch and the PATH-guard message.

Two findings from the pre-ship critique are folded in. The dispatch test asserts the **complete, ordered** argv rather than token presence: order is the invariant that matters, and a token-presence check let three real mutations ship green — `-q --accept-hooks` (Hermes swallows the hooks flag as its query text), a Codex subcommand demoted to a trailing positional, and a deleted stdin redirect. A FIFO-backed regression test now holds the redirect specifically, since inheriting the runner's stdin would pass vacuously wherever stdin is already closed. And the Hermes query carries its own guard: it is the one harness that fails *silently*, because a `-s` resolving to nothing starts the session with no skill loaded instead of aborting — which unattended, with `--yolo --accept-hooks`, would leave a fully-approved agent looping in a git repo on nothing but a one-line instruction.
- `/ship` now reads the PR back after `gh pr merge --auto` and reports what actually happened. Where the base branch requires no status check, `--auto` has nothing to wait on and merges immediately — the command still succeeds, so the previous wording reported an armed auto-merge for a PR that had already landed with CI gating nothing.
- **Changelog fragments replace direct CHANGELOG.md edits**: `/ship` and `/update-docs` now write one fragment per PR to `changelog.d/<issue-or-slug>.<added|changed|fixed|removed>.md`, and `scripts/collect-changelog.sh <version>` folds them into a dated section at release (`--preview` dry-runs, `--check` validates names). Distinct filenames make the changelog merge conflict structurally impossible instead of merely cheap to rebase — it was the one file every PR touched, so it could never be a `serialize_paths` entry without pinning `/worktrees` concurrency at 1. Hand-written `## Unreleased` content is merged by category at release, so in-flight PRs written the old way lose nothing, and `.gitattributes` sets `CHANGELOG.md merge=union` as a backstop. `/worktrees` now documents that `serialize_paths` is for semantic conflicts only and that files every PR touches must be fixed structurally. Covered by `tests/test_changelog_fragments.sh`.
- **README states the protocol-oriented stance; plugin description names the harnesses** — the README now says explicitly what its structure already implied: hephaestus takes a protocol framing toward agents, models, and harnesses, each a neutral spec with pluggable implementations — agent roles rather than vendor bindings, model tiers rather than model IDs, workflow specs rather than one harness's dialect. Framed as a stance rather than an identity claim; hephaestus remains a workflow *pattern*. The plugin marketplace description picks up the same wording as `README.md` and now names the five harnesses the specs render to.
- **README: OODA framing moved out of Install** — the paragraphs describing the OODA loop and the system's composition (five commands, eight phases, five agent roles, memory in external systems, degradation into artifacts) sat under `## Install` after the Requirements line, where they read as installation prose. They now sit above `## Install`, so the intro runs what it is → how it's shaped → why → how to install. Content unchanged.
- **`## Worktrees` config for this repo's own `/worktrees` runs**: declares `max: 6` concurrent sessions and serializes `install.sh`, where installer and distribution work collides semantically. It bounds slots, not conflict handling — a wider cap widens waves only across independent areas. `CHANGELOG.md` and `README.md` are deliberately absent: a path every PR touches by construction makes every pair of issues conflict and pins effective concurrency at 1, so both were fixed structurally instead — the changelog became one fragment per PR, and README stopped being triggered by generated-adapter churn. Repo-internal; nothing in an installed project changes.

### Fixed
- **`/worktrees` adapters spawned the wrong harness** (#129): the Step 6 spawn block's `claude --permission-mode default "/start-issue <N>"` passed through the OpenCode and Codex generators verbatim, so a non-Claude `/worktrees` run launched `claude` with a Claude-only flag. Both localizers now rewrite the spawn CLI and its rationale — OpenCode to `opencode --prompt "/start-issue <N>"`, Codex to `codex "/start-issue <N>"` — for the `osascript` launch and the manual-launch fallback alike. Neither harness inherits plan mode, so `--permission-mode` is dropped rather than mapped. The workflow summary line ("spawn a seeded Claude Code session") is localized too, and both generators now build the routing `description:` frontmatter from the localized first body line rather than the raw one — previously a Claude product name stayed out of the Codex skill router only because the 180-char truncation happened to cut before it. A repo-wide test guard fails on any `Claude Code`, `claude -`, or `--permission-mode` reference surviving in a generated OpenCode or Codex adapter.
- **OpenCode descriptions truncate on a word boundary, identically in every locale** (#137): `sync-opencode-adapters.sh` cut with a raw `${desc:0:180}`, so routing descriptions ended mid-word (`"…and spawn a seeded O"`, `"…an engineering gate and a gener"`) — and since bash substring expansion counts characters under a UTF-8 locale but bytes under `C`/`POSIX`, regenerating under a different `$LANG` produced different files and a spurious `--check` failure. The generator now uses the same `LC_ALL=C` word-whole trim the Hermes generator already had, so words are dropped whole, a multibyte character can never be split, and output is byte-identical under `C`, `POSIX`, and UTF-8 locales. Note the issue's suggested `export LC_ALL=C.UTF-8` is not portable — macOS ships no `C.UTF-8` locale.
- Hermes adapters corrected against a live Hermes v0.15.1 install. The `/worktrees` spawn command was `hermes chat -q "/start-issue <N>"`, but single-query mode bypasses the slash-command dispatcher entirely, so the skill never loaded and the literal text reached the model; it now preloads the skill explicitly with `hermes chat -s hephaestus/start-issue -q "..."`. Delegate briefs no longer claim plain toolset "narrowing" — requested toolsets are intersected with the parent's and anything missing is dropped silently — and now state that a delegate inherits none of the parent conversation. `verify-hermes-load.sh` checks the preload identifier the spawn depends on.
- **Stale-adapter sweeps no longer delete hand-written files** (#145): all four generators removed any unexpected file in a generated directory without checking for the `generated from` marker the skill sweeps already require. A personal command in `.claude/commands/`, agent in `.opencode/agents/`, role in `.codex/agents/`, or note in `.hermes/agents/` was deleted silently on the next sync. Each sweep now reports the file and exits non-zero instead, matching `check_stale_skills`. The issue named Codex and Hermes; the Claude and OpenCode generators had the same hole, and `.claude/commands/` is where users keep their own commands. Relatedly, the Claude and OpenCode generators printed `✓ adapters generated` and exited 0 even after reporting an error — they now exit non-zero like the Codex and Hermes generators, so a reported problem is never masked by a success line.
- **Test fixtures no longer copy gitignored build artifacts** (#146): `setup_fixture` rsynced the working tree with only `.git` excluded, so every gitignored artifact was copied once per fixture — on a checkout where OpenCode has run, `.opencode/node_modules` is ~61MB, or ~800MB across `test_install.sh`'s 13 fixtures. The suite ran 25m53s at 9% CPU locally and sometimes died with `rsync: unexpected end of file`; CI never saw it because CI clones fresh. `test_install.sh` now runs in ~34s and the full suite in ~1m42s. The exclude list is generated by `git ls-files --others --ignored --exclude-standard --directory` rather than handed to rsync as `--filter=':- .gitignore'`: rsync cannot read git's negation syntax and would parse `.hermes/.gitignore` (`*` plus `!skills/**`) as a bare `*`, silently dropping that whole tree from every fixture. The list is built with `env -u GIT_CONFIG_GLOBAL` so the fixture's own git config cannot hide a `core.excludesFile` rule, with `core.quotePath=false` so non-ASCII names still match, and with glob metacharacters escaped so an ignored `a[bc].log` cannot exclude tracked `ab.log`. New `tests/test_fixture_hygiene.sh` pins all three properties: ignored artifacts stay out, untracked working-tree files come in, and uncommitted edits to tracked files under an ignore-all `.gitignore` still reach the fixture.
- **Cursor `readonly:` now reflects what Cursor actually does** (#147): the flag was emitted only for agents with no shell, because whether `permissionMode READONLY` also withheld the terminal was unknown. Probed against Cursor 3.13.21: it runs the shell under a read-only filesystem sandbox — a shell write fails with `operation not permitted` — drops only `SwitchMode`, and leaves both `Shell` and `Write` in the tool list, where the write tool bypasses the sandbox entirely. `reviewer` and `explorer` therefore carry `readonly: true` now, gaining a sandboxed shell they previously ran without. `tester` is exempt through a new `shell: write` frontmatter key, since test runs produce artifacts and a sandboxed shell would fail the test command outright. The generated prose claimed `readonly: true` withholds write tools; it does not, and the write tool is not sandboxed, so the note now says what the flag actually guarantees rather than overselling it. Also drops a stale `.hephaestus/` submodule reference from the generated Cursor rule, left behind by the submodule removal in #140.
- **Hermes delegation now actually happens** (#154): measured against a credentialed Hermes v0.15.1 install (`anthropic/claude-opus-4.6` via the nous provider), the orchestrator never called `delegate_task` at all — it silently inlined every role the workflow named. Nine live `/refactor` runs against fixture repos settle what #153 left open. Delegation was not broken: told explicitly to delegate, the orchestrator batched six coder delegates that each rewrote their own module correctly, so the `context` wording #153 landed is already sufficient — every child received an absolute path in its goal, an absolute `cd` in its verify command, and resolved both without the parent conversation. What failed was reach: the skills described delegation rather than requiring it, and both delegation call sites in the workflow bodies are conditional ("For large refactors spanning multiple modules…", "For independent refactoring tasks across different files…"), leaving the orchestrator free to judge the condition unmet and do the work itself. It always did. The fix is wording in `scripts/sync-hermes-adapters.sh` and needs both halves: `render_hermes_skill`'s callout now states that a step naming a role **must** be delegated, and `hermes_localize_body` rewrites the conditional call sites into imperatives. Each half alone changes nothing — measured 0/1 for the callout alone and 0/1 for the call sites alone, against 0/1 for the original wording and 4/4 with both, all on the same fixture and prompt. Scope: one model, one workflow, six-module fixtures; the counts are small and delegation is stochastic, so treat 4/4 as a strong signal rather than a guarantee.
- **`verify-hermes-load.sh` no longer reports healthy on an ambiguous skill** (#155): the preload check tested only that `hephaestus/start-issue` existed in the project's own skills dir, so it printed `✓ Hermes loads hephaestus skills and delegate briefs` while `/worktrees` was broken. Hermes resolves `hermes chat -s hephaestus/start-issue` via `skill_view`, which refuses to guess when more than one candidate matches and returns `success: false` — the CLI then aborts with `Unknown skill(s)`, killing every spawned window. Two claimants are as fatal as none, and the state is reachable from the README's own instructions: a user-level install symlinks `~/.hermes/skills/hephaestus/*` into the clone while `--vendor` writes real copies that a project then names in `skills.external_dirs`. The check now enumerates every root Hermes searches — its home skills dir plus each `external_dirs` entry, both the block and inline YAML list forms, since under-counting would restore the very false-healthy report the check exists to prevent — and fails when more than one distinct skill claims the identifier, naming each colliding path so the user knows which install to drop. Dedup is by resolved path, matching Hermes: a symlink and its target count once, so a correctly wired machine is not flagged. Regression tests cover the ambiguous case, the symlinked-dedup case, and the inline list. A positional prompt *does* open an interactive session, but Cursor's slash dispatcher is bound to the TUI input widget, so `/start-issue <N>` was never dispatched: it reached the model as literal text. Each site now waits on the state it actually depends on rather than on elapsed time: a non-empty `$LOCK_DIR/pid` (which `loop.sh` writes immediately after taking the lock, so it covers the directory, the pid file, and its contents together), the banner's last `Stop     : kill` line, a non-empty mock args file, and — for teardown — the lock's *absence*. The first test also now clears a stale lock before launching, as the other three already did; without that, a leftover lock makes `loop.sh` exit 1 and the pid file never appears at all. Verified deterministically rather than by re-running and hoping: shimming a slow `shasum` onto `loop.sh`'s PATH delays lock creation past the old one-second window, which reproduces the reported failure verbatim under the old pattern and passes under the new one.

### Fixed
- `start-issue.md` had no branch creation step — commits would land on whatever branch was checked out when invoked standalone (same bug class as the `refactor.md` fix). Added `git checkout -b issue-<number>-<short-description>` after context loading.
- `refactor.md` was missing pre-ship critique gate (reviewer subagent, max 3 iterations), CHANGELOG update step, repo detection via `git remote get-url origin`, and had unbounded test retries. Added Phase 4 (Pre-ship Critique) and Phase 5 (Ship with CHANGELOG + repo detection), capped test retries at max 2.
- Codex orchestrator `SKILL.md` jumped from implement to ship with no critique step — the pre-ship critique was only in `references/workflow-map.md`. Added step 5 (Pre-ship critique) to the main delivery sequence.
- Codex `issue-template.md` was missing `--label` flags — out of sync with the `create-issue.md` fix. Now runs `gh label list` first and passes labels via `--label`.
- `research.md` and Codex `research-issue/SKILL.md` silently dropped the researcher agent's `Confidence` field during synthesis. Added `Confidence` to both output contracts and the research template.
- Codex `research-issue/SKILL.md` was missing the prompt injection security warning present in `researcher.md`. Added matching Security section.
- `CHANGELOG.md` had duplicate `### Fixed` sections under `## Unreleased` — merged into one.
- `update-docs.md` prescribed a different CHANGELOG format (`### [Unreleased] - YYYY-MM-DD` / `####`) than actually used (`## Unreleased` / `###`). Fixed to match actual format.
- `autopilot.md` Phase 8 said "Delete merged branches (local only)" but `finish.md` also deletes remote branches. Updated to "(local and remote)".
- `researcher.md` output contract had `Confidence` after `Sources` instead of before — reordered to match consumer expectations in `research.md` and `research-issue/SKILL.md`.
- Codex orchestrator `SKILL.md` step 7 (Finish) said "Delete merged local branches" — updated to "local and remote" to match `autopilot.md` and `finish.md`.
- `ship.md` was missing `git push -u origin HEAD` before `gh pr create`, causing PR creation to fail when the branch hadn't been pushed yet.
- `refactor.md` was missing a branch creation step — commits would land on whatever branch was currently checked out (typically `master`/`main`). Added `git checkout -b refactor/<short-description>` in Phase 2 and clarified the push step in Phase 4.
- `test-issue.md` referenced `<detected-repo>` in `gh issue view` without a preceding step to detect the repo. Added a "Detect repo" step 1 (consistent with all other commands that use `--repo`).
- `loop.sh` killed itself on the first failed `claude` run: `set -euo pipefail` caused the entire loop to exit when the `claude | tee` pipeline returned non-zero. Removed `-e`, use `PIPESTATUS[0]` to capture claude's exit code, log the error, and continue looping.
- `loop.sh` had no protection against concurrent instances, non-numeric interval arguments, or `claude` being absent from PATH. Added `mkdir`-based atomic lockfile (project-scoped), numeric+range validation, and `command -v claude` guard.
- `finish.md` branch cleanup silently skipped all squash-merged branches: `git branch --merged` never lists them because squash commits are not in the target's ancestry. Replaced with `gh pr view --json headRefName` to get the branch name directly, and switched to `git branch -D` (force delete). Also added `git checkout $BASE` before deletion (cannot delete the checked-out branch) and remote branch cleanup.
- `refactor.md` had no ship path — Phase 4 only printed a report with no commit/push/PR steps. Added Phase 4 (Ship) and renumbered Report to Phase 5.
- `finish.md` was redundantly updating CHANGELOG after `/ship` already did it, causing triple-updates in autopilot runs. Removed; added explicit note that CHANGELOG is ship's responsibility.
- `finish.md` stash pop had no guard — `git stash pop` would error if no stash exists. Now checks before popping.
- `start-issue.md` ran code critique and tests together in one phase with no separate retry path for critique failures. Split into Phase 4 (critique, max 3 retries) and Phase 5 (tests).
- `researcher.md` output contract was missing `Conflicting viewpoints` and `Recommendations` fields that `research.md` expects from subagents, causing data to be silently dropped during synthesis.
- `update.sh` silently missed new agents/commands added after initial install. Now re-runs `install.sh` after pulling to repair and add any new symlinks.
- `reviewer.md` missing test adequacy and CLAUDE.md compliance evaluation dimensions — pre-ship critique gate now checks for untested risky behavior and project convention violations.
- `create-issue.md` drafted labels in body text but never passed `--label` to `gh issue create`. Now runs `gh label list` first and passes labels via `--label` flags.
- `ship.md` and `tester.md` hardcoded `origin/master` in git diff ranges, causing empty output for projects using `main` as the default branch. Now detects the base branch dynamically via `git symbolic-ref` (then `git remote show origin`, then `master` as last resort).
